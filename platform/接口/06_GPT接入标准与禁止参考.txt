玄渊平台——GPT/Codex新功能接入标准与禁止参考清单

一、新窗口开始前必须做的事

1. 先读本目录 00_先看这里_接口总索引.txt。
2. 按功能读取对应的 01至05 文件。
3. 在 active packages 的 manifest.json 中确认包ID、版本、状态、依赖、claims和目标文件。
4. 不从 D:\MirServer、testbeds、backups、legacy_archive 或旧交班记录复制“看起来能用”的接口。
5. 先判断调用者位于 QFunction、独立 QuestDiary/NPC、UI按钮还是引擎事件；调用语法不同。

二、接口选择规则

同一QFunction受管块内：优先 GOTO @公共标签。

独立NPC/QuestDiary文件：只有文档明确给出可调用外部文件时才使用：

#CALL [\路径\脚本.txt] @入口

客户端按钮：在共享 [@CustomButtonClick] 中先判断唯一 CustomButtonID，再进入公共QFunction标签。

世界地图NPC：直接 CALCVAR + SAVEVAR 写公共人物权限；QFunction任务则 GOTO 对应 *_GRANT。

装备属性：只写 profiles\script_properties.json 声明的 outlet，宿主锚点必须唯一存在。

三、新成果包的最低标准

1. manifest 使用UTF-8 JSON，声明唯一 id、version、status、residency、dependencies、claims 和 operations。
2. 公共接口必须在 README 中写清：调用场景、完整命令、参数、前置依赖、状态、失败表现和禁止路线。
3. 入口只负责路由，费用、奖励、状态和实效逻辑保持单一母版。
4. 使用 detect -> preflight -> plan -> apply -> verify -> rollback。
5. 目标脚本按GB18030/CRLF处理；平台母版保持UTF-8。
6. 重复安装幂等；冲突、重复标签、未知锚点或手改受管块时零写入停止。
7. candidate 在独立同引擎新服完成 M2无报错、游戏内验收、回滚验证后才可晋级verified。

四、禁止参考或禁止恢复的路线

1. 世界地图旧测试标签
   @XY_WORLD_MAP_GRANT_NIMUGEFU
   原因：与现行 TOKEN/标签体系不一致。现行宁姆格福授权为 @XY_WORLD_MAP_NMGF_MAIN_GRANT。

2. 世界地图临时玩家命令
   @测试解锁宁姆格福 / UserCmd90
   原因：只为局部测试，且现有候选包指向旧标签，不得进正式服。

3. 回收外部 #CALL
   原因：当前引擎已经实证单文件和拆分文件都 load fail。正式回收核心必须内联在 QFunction 受管块。

4. 狂暴双系统
   禁止 N$XY_RAGE_ACTIVE、旧 @XY_RAGE_TRIGGER、旧 @XY_RAGE_REFRESH、另一套POWERRATE后台和复制扣费分支。
   当前唯一状态是“狂暴之力”称号，唯一业务入口是 @XY_RAGE_NPC_MAIN。

5. 左上图标旧路线
   禁止旧动态按钮88、ButtonClick89透明覆盖、XYTEST_ATTR_BUFF_LOGIN。
   当前使用静态ID3/5 + 动态89至93 + Buff190。

6. 处决旧多层 #CALL
   禁止外部脚本中继续多层调用 @XY_EXEC_CALC_TIER、ChangeSpeedEX旧路线、PVP只加第一刀或只减速不增伤的历史脚本。
   正确处决宿主仍属于实验室，必须由实验室页面管理。

7. 实验室玩家命令
   @UserCmd91（伤害系数试验）、@UserCmd92（对怪吸收试验）只属于历史/隔离测试。
   两项功能已分别形成正式常驻成果包，不得在生产服保留测试命令。

8. 初始背包错误路线
   禁止 EXTBAGOPENITEMCOUNT = 200 和在QManage重复设置。
   当前登录契约为 ExtBagPageCount = 4 与 ExtBagOpenItemCount + 160。

9. 装备显示位重复实效
   BindType 40至48主要是实例显示镜像，禁止再次汇总到伤害链造成双倍叠加。

10. 国王模式内部标签公开化
    XY_KING_* 和 XY_KING_FLOW_* 不得直接做成无权限玩家命令。

五、发现文档与清单不一致时

1. 停止施工，不猜。
2. 以当前唯一 active manifest 为版本和安装事实。
3. 对照 payload、README 和证据判断语义。
4. 如果 README 只是版本号滞后，在接口文档中注明；不要擅自修改业务包。
5. 如果入口本身指向不存在标签，将其列为禁止/待修，不得包装成可用接口。

六、交付验收清单

[ ] 公共入口只有一份业务逻辑。
[ ] 调用场景与 GOTO/#CALL/引擎命令相符。
[ ] 依赖包和状态已写清。
[ ] 标签、变量、UserCmd、按钮、Buff、锚点无冲突。
[ ] 预检零写入且报告可读。
[ ] 安装失败无半成品。
[ ] 重复安装幂等。
[ ] M2无脚本错误。
[ ] 游戏中入口、状态、数值和实效一致。
[ ] 回滚逐字节恢复。

七、维护本目录

平台新增、替换或废弃公共接口时，必须同步：
- 本目录对应说明文件；
- 接口清单.json；
- Codex维护记录中的当前版本施工记录；
- D:\codex交班记录 的索引与最近任务指针。

旧接口不直接删除时，必须在本文件标记“禁止参考”，防止后续窗口误接。
