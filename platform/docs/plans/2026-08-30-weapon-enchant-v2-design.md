# 武器附魔 V2 设计

日期：2026-08-30  
状态：已获用户确认，按现有 verified 装备洗练母版复用修订

## 目标

把当前服已经验收的“开天斩/逐日剑法/烈火剑法必定暴击与致命一击”沉淀到平台，同时复用 `xy.optional.equipment-wash-opening` 已验收的装备洗练界面和普通洗练逻辑。新包只处理武器，不修改 verified 母版，不写数据库，不操作引擎。

## 设计边界

- 包ID保持 `xy.optional.weapon-enchant`，配置路由保持 `weapon-enchant`。
- `xy.optional.equipment-wash-opening` 作为只读黄金母版；其 manifest、脚本、资源与验收证据逐字节不改。
- 武器附魔派生母版仅允许 StdMode 5、6，默认每次100元宝，消耗可由42号表修改。
- 保留普通洗练、仙级、圣级、天赐和神佑既有流程；新增技能特殊结果池。
- 技能特殊结果默认六条：开天斩、逐日剑法、烈火剑法分别对应必定暴击和致命一击。
- 候选不限行数，使用稳定词条编码，不以Excel行号为身份。
- 候选概率使用整数权重；平台自动计算展示概率，并用逐级 `RANDOMEX 子数 母数` 编译精确权重。
- 技能词条保存到本包受管的武器实例身份行，运行时从武器实例读取稳定ID并在 AttackDamage 链按技能ID生效。
- 普通已有词条通过平台路由库声明 `legacy_pool`、`native_bind`、`script_runtime` 或 `candidate`。没有真实出口的启用候选必须阻止预检，不能只显示文字。
- 等级与等级上限仅预留路由名。09号表“等级”是 NeedLevel；当前没有“人物等级+X/等级上限+X”的装备实例实效证据，因此不得进入正式随机池。

## 工作簿 V2

正式文件仍为 `所需材料表格汇总/42_武器附魔.xlsx`，改为以下中文表：

1. `基础设置`：目标部位、允许StdMode、NPC、ITEMBOX、消耗类型、消耗数量、普通洗练权重、显示前缀和受管身份行。
2. `结果候选`：词条编码、显示名称、属性来源、属性名称、适用技能、效果类型、效果值、概率权重、实际概率、颜色、是否启用。
3. `普通洗练设置`：复用母版的神佑/天赐/圣级/仙级/传说/上古/灵级阈值及启用状态。
4. `词条路由库`：平台生成的只读中文目录，列出真实路由、状态和适用边界；用户不填写引擎变量或命令。
5. `填写说明`：最短操作说明、状态解释与实例恢复边界。

旧五表工作簿继续兼容读取，并折算为V2候选；正式42号表使用V2。

## 事务与安全

- detect → preflight → plan → backup → install/update → verify → rollback。
- QFunction共享事件仅使用唯一受管块；冲突或重复标签阻止。
- 脚本按GB18030/CRLF输出。
- 每次实例写入保持单一连续 `LockUpdateItem → 清理本包受管行 → 写入 → UpdateItem`。
- 文件回滚与玩家武器实例恢复分别说明；文件回滚不会还原已洗练的玩家实例。
- 当前服本轮只用于只读冻结预检，不执行安装。

## 验收门禁

- verified装备洗练母版哈希和测试不变。
- 六条技能候选、任意N候选、稳定ID、精确权重、路由阻断、GB18030/CRLF、无数据库命令均有自动测试。
- 旧42号表兼容测试通过。
- 新42号表所有工作表完成公式、错误值与视觉渲染检查。
- 专项、相关全量、正式GUI/CLI构建通过。
- 用新42号表对当前服运行冻结CLI只读预检；只报告变化，不写当前服。若默认生成物与已验收当前服一致，目标为 changes=0；若保留verified普通洗练派生导致差异，则必须准确列出且保持 candidate/待验证。
