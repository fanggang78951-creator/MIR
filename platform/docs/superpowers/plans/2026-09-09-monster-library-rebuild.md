# 怪物库完整动作资料重建实施计划

> **执行约定：** 全程不操作游戏引擎、M2、服务端或客户端；先生成候选物，再决定正式提升。用户的日常入口始终是 `所需材料表格汇总/20_怪物批量生成.xlsx`。

## 1. 定位现有契约与供体输入

**读取：** `src/xydp/monster_library.py`、`src/xydp/monster_catalog_v3.py`、`src/xydp/monster_workbook.py`、怪物接口文档、明月 `pak.txt`、供体数据库及旧库索引。  
**验证：** 确认 GUI 和一键植入使用的目录、V3 字段、标准 Appr 映射和 PAK 密码读取方式。  
**完成标准：** 输出一份字段映射和输入可用性摘要；不修改任何生产文件。

## 2. 建立无解码的原始动作帧清单

**新增候选输出：** `怪物库/build/20260909-rebuild-candidate/raw-frame-manifest.jsonl`、摘要报告。  
**实现：** 只扫描 `E:/素材/传奇2怪物PNG`、`E:/素材/传奇2怪物BMP` 的一级动作组目录及其中数字帧文件名；记录库号、槽号、格式、帧数量、首末帧、文件大小与流式哈希。  
**验证：** 同组 PNG/BMP 的编号和帧序一致性；缺一格式不视为失败，但明确标注。

## 3. 建立供体运行补丁清单

**新增候选输出：** `runtime-patch-manifest.jsonl`、`runtime-patch-conflicts.json`。  
**实现：** 从供体怪物数据库、`pak.txt` 和实际 `Mon*.PAK`/WZL/WZX 文件生成 Appr→库号/槽号→资源→密码的清单；旧库仅补充来源线索。  
**验证：** 资源文件存在、密码规则非空或明确无需密码、同一 Appr 无冲突映射。

## 4. 生成 V3 兼容候选怪物库

**新增候选输出：** `catalog.sqlite`、`assets-manifest.json`、`unready-records.csv`、`validation-report.json`。  
**实现：** 合并动作帧清单与运行补丁清单；标准 Appr 只有双侧闭环才成为 `ready_verified`。SmartMonster 按完整闭环规则单独分类。生成精确、不混淆的不可用原因。  
**验证：** SQLite `integrity_check`、模型库记录编号唯一、资源路径/哈希、ready 记录全闭环、与工作簿导入器的选择规则一致；同一模型编号被多行怪物重复引用必须允许。

## 5. 以真实工作簿做离线模拟

**读取：** 当前正式 `20_怪物批量生成.xlsx`，只读用户现有行。  
**输出：** 候选目录中的模拟报告和失败行清单。  
**实现：** 复制工作簿到候选目录；对全部待安装行按“显式模型 / 自动随机”执行与平台相同的解析规则，不写 `ApexM2.DB`，不复制补丁。  
**验证：** 所有留空模型编号的行均能稳定选中 `ready_verified` 模型；同一有效模型编号可被多行重复选择；显式不合格模型会给出可理解的闭环缺项。

## 6. 正式提升与工作簿参考页更新（仅候选验证通过后）

**备份：** 现有 `怪物库/catalog.sqlite`、当前正式工作簿以及将受影响的库元数据。  
**实现：** 原子替换已验证的 catalog/索引；复用现有 GUI，不引入第二个入口。更新模型参考页为实际 ready 清单，同时完整保留用户填写的“怪物生成”行；模型列仍可留空。  
**验证：** GUI 刷新列表条数、工作簿预检、模拟一键植入、备份与回退演练。正式客户端/服务端写入及游戏验收不在本步骤执行。

## 7. 沉淀与交接

**修改：** 更新怪物资料接口说明，记录“原始帧归档 + 原 PAK 运行补丁”的规则、可用状态定义和排障指引。  
**验证：** 新工作簿从零填写一行、模型留空时的静态预检可通过；最终由用户在真实游戏验证怪物显示和动作。
