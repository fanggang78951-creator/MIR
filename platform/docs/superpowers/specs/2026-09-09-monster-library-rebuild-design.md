# 怪物库完整动作资料重建设计

**日期：** 2026-09-09  
**状态：** 已批准实施（用户目标：只填写 `所需材料表格汇总/20_怪物批量生成.xlsx`，平台一键生成）

## 目标

将平台的怪物库重建为可被“怪物批量生成”直接消费的完整模型库。用户只填写怪物名称和基础数值；`模型库编号`始终允许留空，由平台从可用模型中稳定随机选择。平台在植入时同步该模型对应的客户端运行补丁。

## 权威输入

1. `E:/素材/传奇2怪物PNG`：完整 PNG 动作帧归档。
2. `E:/素材/传奇2怪物BMP`：与 PNG 对应的完整 BMP 动作帧归档。
3. 明月供体端现有怪物数据库、`pak.txt`、`Mon*.PAK`：运行时补丁、Appr 和密码规则来源。
4. 现有旧怪物库仅可用于映射线索，不继承其“ready”状态。

不对 PNG/BMP 做图像解码、画面识别或像素验收；用户已确认其为完整且等价的动作素材。只读取目录名、顺序帧文件名、数量和文件字节哈希以建立可追溯索引。

## 运行模型

- 标准 Appr 怪物：优先复用供体 `Mon*.PAK` 作为客户端运行补丁，保留原资源偏移、动作序列和原始加密规则；PNG/BMP 作为动作完整性归档与编号依据。
- WZL/WZX 仅在供体原本即使用该形式时按原形式登记；不把 PNG/BMP 临时重编码成运行补丁。
- SmartMonster/自定义怪物必须额外具备 INI、EffectImageList、客户端资源、M2 DAT 和登录器集成闭环；缺任一项只登记为“待补全”，不进入自动随机池。
- `library_no = Appr // 10 + 1`，`slot_no = Appr % 10`；此映射仅在供体数据库与补丁清单一致时登记为可用。

## 可用状态

只有同时满足以下条件的记录才写入 `ready / ready_verified`，并可供工作簿显式选择或自动随机：

1. 有唯一的模型库记录编号、名称和引擎模式；
2. 有可定位的完整原始动作帧组（PNG 和/或 BMP）；
3. 有存在的客户端运行资源及其精确来源/密码规则；
4. 标准 Appr 的库号、槽号、Appr 和 PAK 规则一致；或 SmartMonster 满足完整集成闭环；
5. 生成的资源清单可复算且不含冲突。

缺项记录保留在目录中并说明原因，但绝不进入自动池；错误提示须区分“编号不存在”与“编号存在但资料未闭环”。

模型编号是**外观模型编号**，不是怪物业务编号：一个已验证模型编号可被任意多只怪物重复填写和使用。工作簿不得因重复模型编号报错、改号或拆分补丁；只校验该编号本身是否真实可用。

## 交付体验

用户只操作：

1. 填写 `E:/XuanYuanDevPlatform/所需材料表格汇总/20_怪物批量生成.xlsx` 的名称与基础属性；
2. 不填模型编号；
3. 在平台“怪物库”页面选择该表并点击“一键同步怪物”。

平台负责稳定随机模型、补丁闭环、同名怪物更新、预检、备份、安装回执和登录器要求提示。刷怪点、爆率、NPC 和地图不属于本次范围。

## 边界与风险控制

- 第一阶段只在 `怪物库/build` 下生成候选库、清单与验证报告，不改现有 `catalog.sqlite`、客户端、服务端、工作簿。
- 正式替换前备份现库、保留可回退目录，并做 SQLite 完整性与工作簿模拟植入验证。
- 不覆盖用户已填写的“怪物生成”行；模型参考页只在确认安全后更新，必要时保留同目录备份。
- 游戏内动作、补丁显示和登录器生成仍需用户最后验收；静态验证不得伪称游戏验收。
