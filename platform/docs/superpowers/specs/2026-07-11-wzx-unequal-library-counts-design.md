# WZX 三图库数量不一致兼容设计

## 目标

允许 `Items`、`StateItem`、`DnItems` 拥有不同历史偏移槽数量；来源编号只需在各自图库中存在有效偏移。新增静态装备图标仍使用同一个 Looks 编号。

## 规则

- 读取时以 WZX 文件物理偏移槽为准；头部 count 仅记录诊断信息，不因差 1 直接阻止。
- 不要求三套图库历史数量相等，也不要求三套 WZL 头部 count 相等。
- 新 Looks 取三套物理槽数量的最大值；短库在备份后的工作副本补 `0` 偏移到该编号。
- 每套图库从自己的来源编号提取原始帧并追加，禁止跨库复用同一帧。
- 追加完成后三套 WZX/WZL 头部统一为 `new_looks + 1`，三套目标帧分别做 SHA-256 一致性验证。
- 任一追加或验证失败时，用任务备份恢复六个客户端文件。
- 不直接修改 `D:\11周年\data` 做算法试验；先在临时副本验证。

## 验收

- 当前来源 1404 的只读装备预检不再因 count 不一致阻止。
- 4/2/3 槽的合成三图库生成共同 Looks=4，生成后均为 5 槽。
- 补位槽保持 0，三套新帧分别等于各自来源帧。
- 全量平台/装备测试和更新版 EXE 构建通过。
