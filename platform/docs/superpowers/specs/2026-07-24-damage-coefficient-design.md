# 伤害系数独立乘区设计

状态：待验证  
设计日期：2026-07-24  
建议实验包 ID：`xy.lab.damage-coefficient`  
正式包预留 ID：`xy.combat.damage-coefficient`

## 1. 目标

新增平台脚本属性“伤害系数”，它与神力倍攻在数学公式上分属两个独立乘区。

> 2026-07-25实测修正（优先于下文旧候选路线）：本端同时执行`POWERRATE type0/type1/type2`时，后执行的type1/type2会使神力type0失效。正式候选路线改为先独立汇总神力与伤害系数，再用`CalcPercent`计算`神力×伤害系数÷100`，最终只执行一次type0。下文关于“用type1/type2直接承载伤害系数”的内容仅保留为失败路线证据，不得实施或进入平台。

简化公式：

```text
最终伤害 = 引擎基础伤害 × 伤害系数乘区 × 神力倍攻乘区 × 其他已生效乘区
```

“引擎基础伤害”是引擎完成攻击/魔法/道术、技能、目标防御和随机浮动后的实际基础伤害，不直接等同于面板攻击上限。

## 2. XLSX 数值规则

正式规则建议固定为：

- XLSX 填 `0`：没有伤害系数加成，乘区为 `100%`，即 `1.00` 倍。
- XLSX 填 `10`：伤害系数 `+10%`，乘区为 `110%`，即 `1.10` 倍。
- XLSX 填 `50`：伤害系数 `+50%`，乘区为 `150%`，即 `1.50` 倍。
- XLSX 填 `100`：伤害系数 `+100%`，乘区为 `200%`，即 `2.00` 倍。

同一个“伤害系数”乘区内部采用加法汇总：

```text
伤害系数+20%装备 + 伤害系数+30%装备
= 伤害系数总加成50%
= 1.50倍
```

不同乘区之间再相乘：

```text
基础伤害1000
伤害系数+50% = 1.50倍
神力倍攻+100% = 2.00倍
结果：1000 × 1.50 × 2.00 = 3000
```

因此它不能写入 `N$倍攻` 或 `N$XY_RT_Power`；写进去会变成同一乘区相加，失去独立乘区含义。

## 3. 生效范围

默认设计为：

- PVE 生效。
- PVP 生效。
- 战士物理攻击、法师魔法攻击、道士道术攻击均应覆盖。
- 普通攻击和技能伤害均要求验证。
- 不影响固定切割、首刀斩杀、尾刀斩杀、鞭尸和爆率。

固定切割仍是 `ChangeDamageValue` 追加值，不进入伤害系数乘区。处决额外伤害是否接受伤害系数，首版保持不接入，避免实验功能互相污染。

## 4. 引擎实现路线

### 4.1 乘区占用

保留现有神力倍攻：

```text
POWERRATE ... type0
```

伤害系数实验包预留：

```text
POWERRATE ... type1  # 对人物/PVP
POWERRATE ... type2  # 对怪物/PVE
```

历史本服证据已经确认 `type0 × type2` 可得到独立相乘结果；但当前正式“打怪伤害”已改走 `ChangeDamageValue`，平台禁止把未经复验的 `type2` 直接发布。因此本设计必须先作为独立实验包验证，不能直接写入 verified 包。

### 4.2 统一变量与锚点

建议变量：

```text
N$XY_RT_DamageCoeff
```

每次统一重算先恢复基准：

```text
MOV N$XY_RT_DamageCoeff 100
```

装备只向独立锚点累计：

```text
; XY_EQUIP_MAKER_RUNTIME_DAMAGE_COEFF_ANCHOR

#IF
CHECKITEMW 某装备 1
#ACT
INC N$XY_RT_DamageCoeff 10
```

最终只允许统一出口各写一次PVP和PVE倍率。装备、称号、赞助和临时BUFF都不得各自直接执行 `POWERRATE type1/type2`。

### 4.3 刷新入口

必须同时覆盖：

- 真实登录脚本。
- 穿戴事件。
- 卸下事件。
- `[@AttackDamage]` 运行时自愈重算。

登录和穿脱保证下一次攻击前已刷新；`AttackDamage` 只用于防止历史残留和漏事件。卸下全部装备时必须把 type1/type2 都恢复为 `100`。

### 4.4 资源占用声明

实验包和未来正式包必须声明独占：

```text
powerrate:type1
powerrate:type2
```

预检扫描到任何其他脚本直接写 type1/type2 时必须阻止，不能覆盖。类型0继续由神力/狂暴统一倍攻体系拥有。

## 5. 装备生成与显示契约

建议脚本属性：

```json
{
  "伤害系数": {
    "unit": "%",
    "display_bind_type": 53,
    "runtime_variable": "N$XY_RT_DamageCoeff",
    "anchor": "XY_EQUIP_MAKER_RUNTIME_DAMAGE_COEFF_ANCHOR"
  }
}
```

M2 自定义装备属性显示建议使用下一空位 `BindType 53`，文字：

```text
伤害系数: +
```

静态绿字：

```text
伤害系数:+10%
```

显示与实效必须分开验证。`ItemDescList` 或 BindType 能显示，不代表 type1/type2 已实际生效。

## 6. 禁止路线

- 禁止把伤害系数累加进神力变量。
- 禁止使用 `ChangeDamageValue` 冒充全局独立乘区。
- 禁止使用原生“攻击伤害”列冒充“伤害系数”。
- 禁止每件装备直接执行 `POWERRATE`。
- 禁止多个功能同时占用 type1/type2。
- 禁止未经PVE、PVP和三职业验证就进入正式包或常驻基础。

## 7. 实验包验收矩阵

至少准备两件单属性测试装备：`伤害系数+50%`、`神力倍攻+100%`。

| 场景 | 预期 |
|---|---|
| 两件都不戴 | 1.00倍基准 |
| 只戴伤害系数+50% | 约1.50倍 |
| 只戴神力+100% | 约2.00倍 |
| 两件同时佩戴 | 约3.00倍，不是2.50倍 |
| 伤害系数+20%与+30% | 约1.50倍，不是1.56倍 |
| 卸下全部 | 恢复1.00倍，无历史残留 |
| 重登 | 数值保持正确 |
| PVE连续攻击 | 普攻与技能均按相同比例提升 |
| PVP连续攻击 | 普攻与技能均按相同比例提升 |
| 固定切割 | 固定值不被伤害系数放大 |
| 处决 | 首版不被伤害系数放大 |
| 冲突脚本写type1/type2 | 平台预检阻止 |
| 回滚 | QFunction及状态文件逐字节恢复 |

伤害存在随机浮动时，每组至少记录20次并比较平均值；同时记录第一刀和第二刀，确认没有“第一刀旧倍率”问题。

## 8. 晋级顺序

1. 建立 `xy.lab.damage-coefficient`，只进入独立实验室页面。
2. 在全新同引擎测试服安装，提供测试装备或测试命令。
3. 完成M2零脚本错误、PVE、PVP、三职业、穿脱、重登、冲突和回滚验收。
4. 验收通过后建立 `xy.combat.damage-coefficient` 正式包。
5. 再把“伤害系数”加入 `script_properties.json`、两张装备XLSX、批量生成/修改链、M2显示说明和左上属性图标可选来源。
6. 在正式装备链复验后才允许标记 `verified`；是否加入常驻基础另行决定。

## 9. 当前结论

数学设计可行；type1/type2同时长期占用路线已被本端实测否定，现改为合成后统一type0并等待游戏复验。当前仍不代表平台已经能生成或安装“伤害系数”装备。
