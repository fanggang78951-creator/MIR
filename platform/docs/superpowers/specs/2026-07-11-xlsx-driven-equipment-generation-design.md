# XLSX 驱动的批量做装备设计

## 目标

让 `D:\XuanYuanDevPlatform\做装备\templates\XuanYuanItems.xlsx` 中的“名称、部位、来源编号和属性”成为批量做装备的唯一业务输入；平台不再要求用户填写旧服务端的模板装备名称。

## 已确认的输入契约

工作表“装备导入表”已经包含：

- 名称：新装备的唯一名称。
- 部位：决定目标 `StdMode`。
- 来源编号：用户在 `Items.wzx` 选择的静态图片编号。
- 基础属性、固定属性和脚本属性：严格按现有 57 列读取。

`模板` 和 `Shape` 不是此 XLSX 的业务列。

## 自动基础母版选择

1. XLSX 未提供模板名称时，解析阶段不得再写入 `测试戒`、`雷纹链`、`青铜靴`、`青铜带` 等旧服固定名称。
2. 预检/安装进入已选择目标服的 SQLite 数据库后，按 XLSX `部位` 对应的 `StdMode` 查找基础记录。
3. 选择规则：只接受 `StdItems.StdMode == 该部位标准值` 的记录；按 `Idx` 升序取第一条。
4. 找不到候选记录时，按 `做装备/profiles/slot_base_profiles.json` 取该 StdMode 的平台基础结构；该结构只包含基础数据库字段，不能包含旧服名称、图标、脚本、掉落或业务属性。不存在平台基础结构时才阻止生成。
5. XLSX 未来若增加可选 `模板` 列，显式模板仍优先；它必须存在且 StdMode 与部位一致。

标准 StdMode 保持现有已验证映射：戒指 22、项链 19、手镯 26、鞋子 62、腰带 64、头盔 15；其他已注册部位沿用 `STD_MODE_BY_SLOT`。

## 资源与 Shape 规则

1. 来源编号仅表示静态图库来源。平台在预检时自行校验 `Items`、`StateItem`、`DnItems` 三套同编号来源帧并分别复制；用户不负责三库匹配。
2. 来源编号已有平台资源映射且其中有 Shape 时，资源映射的 Shape 优先。
3. 对武器、衣服、男衣服、女衣服、盔甲：若无 Shape 映射，自动继承自动选中的目标服基础母版 Shape（用户已选择方案 A）。
4. 静态图标仍严格使用来源编号；继承 Shape 只决定角色手持/穿戴动作的回退形态。

## 属性显示规则

1. XLSX 的脚本属性继续走现有统一 QFunction 出口，不改为 M2 自定义绑定属性位。
2. 同一脚本属性必须同时写入 `ItemDescList.txt` 作为鼠标提示文字；显示文字、单位沿用 `script_properties.json`。
3. 提示文字是显示证据，不替代游戏内的实际脚本效果验收。

## QFunction 事件回退

鞭尸概率优先使用已存在的历史 `XY_EQUIP_MAKER_CORPSE_ANCHOR`。新服没有该锚点但具有标准 `[@KillMon]` 事件时，平台在该事件的 `#ACT` 后插入受管的 `XY_EQUIP_MAKER_CORPSE_INIT` 与锚点，初始化 `N$XY_CorpseRate` 并接入装备聚合分支；没有 `[@KillMon]` 时必须阻止。奖励与死亡事件的实际表现仍列为游戏验收项，平台不从旧服复制地图、怪物或奖励物品。

## 安全与事务

- 自动模板选择仅发生在临时服务端副本中；预检只报告选中的内部基础母版，不写入目标服。
- 确认生成仍通过现有事务、哈希检查和逐字节服务端回滚。
- 客户端静态图库继续使用现有独立备份和三库原始帧校验。
- 不修改 XLSX、现有属性列、QFunction 统一出口或旧成果归档。

## 验收

自动测试至少覆盖：

1. 戒指等没有 XLSX 模板列时，按目标 DB 的同 StdMode 基础记录成功预检与生成。
2. 无同 StdMode 记录时，使用不含业务内容的平台基础结构；无该结构时明确阻止且不写目标。
3. 显式模板存在但 StdMode 与 XLSX 部位冲突时阻止。
4. 无资源 Shape 映射的武器继承自动基础母版 Shape；静态图标来源编号不变。
5. 神力倍攻、打怪伤害、暴击伤害、固定切割、爆率、首刀、尾刀和鞭尸等脚本属性在 ItemDescList 提示行可见。
6. 既有 XLSX 解析、资源三库、事务、回滚测试持续通过。
