# 命格多属性无工作簿容量门禁设计

日期：2026-09-08  
状态：待用户审阅  
适用范围：`mingge-content` 路由、41号结构及使用该结构的外部中文工作簿  
不适用范围：数据库、客户端资源、游戏引擎操作、旧37号命格回滚入口、其他平台功能

## 1. 目标

取消当前“整张工作簿最多11种聚合实效属性”的阻止条件，使包含28种或更多已登记属性的命格候选池可以预检和生成，同时保证：

1. 第12种及以后属性不能被截断、覆盖或降级成纯显示。
2. 每条属性继续区分显示文字与真实效果。
3. 命格实例仍以稳定命格ID为身份，不使用Excel行号或TextVar行号作为身份。
4. 旧测试候选可以退出抽取池，但已有灵玉仍能按旧ID显示并产生原有属性。
5. 当前服在平台开发阶段保持零写入；正式植入与游戏验收另行执行。

## 2. 当前根因

当前实现把装备实例第9至16行用于保存八个槽位的命格TextVar和稳定ID，把第1至8、17至19行固定用作属性汇总，因此只有11个汇总行。

`_content_aggregates` 按整张工作簿所有启用候选的属性类型求并集。并集超过11时预检阻止；如果只删除判断，后续 `zip(CONTENT_PROPERTY_ROWS, aggregates)` 仍只会写前11项，其余属性会静默丢失。因此必须替换存储方式，不能只删报错。

## 3. 数据模型

### 3.1 候选状态

命格定义的“启用”字段扩展为三态：

- `是`：活动候选，参与随机抽取，也可供已有实例重算。
- `退役`：不参与随机抽取，但保留稳定ID、TextVar行、显示和实效重算，供已有灵玉兼容。
- `否`：草稿候选，不编译、不抽取，也不为已有实例提供兼容。

更新时，已存在于目标内容提供者中的稳定命格ID继续沿用原TextVar行。退役候选不得释放或复用其TextVar行。

### 3.2 属性执行计划

每个属性编译成明确执行计划：

- `runtime_aggregate`：从八个槽位的稳定命格ID聚合，在统一重算入口应用；不占装备属性汇总行。
- `native_record`：确实必须由自定义装备原生记录承载的属性；只为当前装备实际需要的原生类型分配第1至8、17至19行。
- `static_only`：只有说明文字、没有真实出口；继续阻止安装。

已有 `textline_runtime` 和具备统一重算变量的 `script_bind` 全部归入 `runtime_aggregate`。已确认存在脚本重算出口的原 `direct` / `script_bind` 属性也迁移到 `runtime_aggregate`。没有可靠清零与重算出口的属性不得伪装迁移。

## 4. 生成与重算流程

1. 装备第9至16行继续只保存八个槽位的TextVar行和稳定命格ID。
2. 内容提供者根据这八个稳定ID读取候选属性，在 `@XY_MG_CONTENT_RECALC_ALL` 中聚合所有 `runtime_aggregate` 属性。
3. 每一种运行时属性必须先归零，再累加八槽贡献，最后调用唯一的既有实效出口。
4. `native_record` 属性按当前实例实际出现的类型动态重建到第1至8、17至19行，不再按整张工作簿属性并集预占。
5. 整个实例更新保持一条连续事务：`LockUpdateItem` → 更新目标槽位ID → 清理本包原生汇总行 → 重建当前实例所需原生行 → `UpdateItem` → 统一运行时重算。
6. 攻速突破继续使用现有Bind60/TextLine40及 `@XY_AS_CAP_RECALC`；命格不得创建第二个 `ChangeSpeed 2` 或新的阈值。

## 5. 门禁审计结果

### 5.1 取消或降级

1. 删除“整张工作簿属性并集不得超过11种”的硬门禁。
2. 删除固定 `zip` 截断路径，改为执行计划生成；任何未生成的实效属性都必须成为明确错误。
3. “彩色文字128字符”不再作为未经证实的硬上限。改为按GB18030序列化后的实际字节数给出警告和预览；只有真实解析失败或目标脚本无法序列化时才阻止。
4. 不再因为候选数量、整张表属性种类数量增加而阻止，只校验稳定ID、引用和真实出口。

### 5.2 必须保留

1. 属性为 `static_only` 或没有真实清零/重算出口。
2. TextVar目标行被其他系统占用，或旧稳定ID映射发生冲突。
3. 攻速突破核心、TextVar40或唯一受管块缺失/重复。
4. QFunction、公共桥、NPC受管锚点重复、残缺或属于其他系统。
5. 路径越界、服务端类型错误、非可解码业务脚本、预检后输入或目标哈希漂移。
6. 稳定命格ID重复、引用不存在、颜色方案不存在、表头/整数/枚举非法。
7. 当前实例实际需要的 `native_record` 类型超过11且缺少运行时出口。此时必须列出具体属性名，不能使用“整张工作簿28种”这种笼统提示。
8. 安装、原子提交和回滚完整性检查。

NPC规则包中的槽位连续性、装备部位与位置匹配、消耗类型、品质持久计数范围等属于生成合同，不在本轮取消。

## 6. 错误与提示

预检报告新增三组明细：

1. `运行时聚合属性`：列出不占装备行的属性。
2. `原生记录属性`：列出占用装备行的属性及当前最大需求数。
3. `无真实出口属性`：逐项阻止并说明缺少的应用/清零出口。

成功预检不得再显示“工作簿实际为28种”的容量错误。文字长度超过历史保守值时只显示警告及实际GB18030字节数。

## 7. 兼容与迁移

1. 已有内容提供者中的 `; CANDIDATE <ID> TEXTVAR <LINE>` 是旧ID映射来源。
2. 活动候选改为“退役”后，仍生成对应候选分支、TextVar和重算分支，只从随机池移除。
3. 新候选使用新稳定ID和新的空闲TextVar行，不复用退役行。
4. 文件回滚只恢复脚本和TextVar；不会自动恢复已经改变的玩家装备实例，实例迁移必须独立列出。
5. 新版属于新的候选版本，不能继承旧版完整游戏验收身份。

## 8. 测试门禁

严格执行红—绿测试：

1. 当前28种属性工作簿在旧实现下因11种门禁失败；新实现预检通过且没有属性截断。
2. 12种、28种和超过28种属性均生成完整执行计划。
3. 运行时属性不占第1至8、17至19行；原生属性动态分配且不重复。
4. 每条属性都有显示和实效路由；`static_only` 仍阻止。
5. 活动、退役、禁用三态：退役不抽取但可显示、可重算，旧TextVar行不复用。
6. 单次实例写入只有一对有效的 `LockUpdateItem` / `UpdateItem`，且属性判断不把更新出口包进某个候选分支。
7. 攻速突破只调用现有统一重算一次，不新增 `ChangeSpeed 2`。
8. GB18030/CRLF、TextVar冲突、受管块冲突、输入/目标漂移、路径越界、无数据库命令全部回归。
9. 旧41号样例、NPC规则包和P3兼容测试继续通过。
10. 平台全量、做装备全量、GUI/CLI正式构建与冻结来源核验通过。

## 9. 验收边界

平台自动测试通过只证明生成、事务和静态路由完整。正式发布后需在目标服验证：

1. 新候选池不再抽出退役测试命格。
2. 已有测试命格灵玉仍保持原显示和原属性。
3. 洗出包含第12种以后属性的候选时，显示、属性面板和战斗实效一致。
4. 穿戴、脱下、登录和覆盖槽位后统一重算无残留。
