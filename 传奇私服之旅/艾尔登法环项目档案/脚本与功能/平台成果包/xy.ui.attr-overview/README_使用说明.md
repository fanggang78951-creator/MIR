# 玄渊左上五图标状态入口

包ID：`xy.ui.attr-overview`  
版本：`2.0.5-candidate.1`  
状态：`candidate / optional`

本包统一管理左上方五个动态图标，不改世界地图图标，不复制任何战斗实效逻辑。

## 五个图标

1. 狂暴：直接检查“狂暴之力”称号；未激活显示黑白，激活显示彩色；点击后直接打开地图0狂暴NPC的同一业务接口。本包不判断费用、不扣费、不写属性。
2. 复活：不可操作；有至少一次复活机会时显示彩色，最后一次机会消耗后显示黑白并实时倒计时。
3. 属性A：神力倍攻、伤害系数、暴击伤害、打怪伤害。
4. 属性B：首刀斩杀、尾刀斩杀、鞭尸概率、对怪吸收。
5. 属性C：韧性、处决概率、处决时间、处决倍数。

属性A/B/C点击均为无操作，只保留鼠标经过悬浮说明。

## 复活规则

- 总机会按有效佩戴件数计算，最多2次：1件显示并拥有1次，2件显示并拥有2次。
- 第1次由引擎原生复活装备完成。
- 只有检测到2件有效装备时，原生复活触发后本包才执行一次`SetReborn 1 <原生剩余冷却>`，形成第2次机会；只佩戴1件时绝不补发。
- 两次机会共用原生60秒窗口，不建立两套独立计时器。
- 例：第一次在第0秒消耗，第二次在第50秒消耗；此时图标变黑白并显示剩余约10秒，原窗口结束后恢复2次机会。
- 第二次机会未使用时，也会随原生窗口结束而失效；下一轮按当前有效佩戴件数恢复1次或2次。
- 脱下本包登记的复活装备时，只清理本包自己补发且仍未使用的那一次机会。

可用装备名单在服务端`Mir200\Envir\QuestDiary\玄渊配置\复活图标配置.txt`中维护，初始只有`复活戒指`，最多预留8个名称。配置文件已存在时升级不会覆盖。

本候选包要求`Mir200\!setup.txt`保持`RevivalTime=60000`。它与其他同样拥有`SetReborn`的玩法需要先做所有权协调；当前目标服静态扫描未发现其他`SetReborn`脚本。

## 按钮和资源

- WIL资源：17（`Prguse.wzl`）。
- 狂暴入口使用界面静态按钮ID 3的`CustomButtonClick`；激活后用动态按钮89显示彩色1776–1778，未激活时保留静态黑白按钮。
- 复活按钮：90；彩色1782–1784，黑白1785–1787；倒计时Buff ID 190。
- 属性A/B/C按钮：91/92/93；图片1772–1774、1791–1793、1794–1796。
- 属性A默认坐标：左246、上17；这是用户在大画布确认并完成游戏验收的最终坐标。
- 世界地图使用界面静态按钮ID 5；本包在共享`CustomButtonClick`中把ID 5转发到既有`@ButtonClick88`地图脚本，不复制地图逻辑。

目标客户端必须已经包含`Prguse.wzl/wzx`的1772–1796资源。本包当前只植入脚本，不覆盖客户端公共图库。

## 可配置属性

安装参数分别使用`panel_a`、`panel_b`、`panel_c`。每组支持：

- `namespace`：A/B/C等独立英文命名空间，避免三组镜像变量串值；
- `source`：业务脚本维护的最终变量；
- `bind_type`：可选的装备自定义属性位；
- `read_mode`：`source`读取业务最终变量、`bind`读取装备属性位、`zero`从0开始按装备规则累加；省略时保持原有自动选择；
- `equipment_additions`：安全声明式装备规则，只允许装备名、数量和加减数值，不允许写入任意脚本；
- `offset`：显示前扣除基准；
- `divisor`：显示除数，例如处决万分比除100后显示百分比、毫秒除1000后显示秒；
- `prefix`、`suffix`、`color`、`clamp_min`。

业务脚本仍负责实际伤害。默认神力和打怪伤害读取已经验证的最终变量并扣除基础100；伤害系数、暴击伤害继续读取BindType 53/42；首刀、尾刀、鞭尸、对怪吸收按当前实效装备分支同源汇总。禁止再把神力、怪伤和属性B改回40/41/46/47/48直读。以后仍可通过安装参数替换任意一组，不需要在成果包内执行任意代码。

“对怪吸收”只用于图标短名称；装备说明继续使用“对怪伤害吸收”。两者不需要统一，也不得因此修改实际吸收命令。

## 安装与验证

1. 先安装并验证“地图0 NPC唯一入口”狂暴包。
2. 确认客户端已包含上述图标帧，且M2已关闭。
3. 在成果包库选择本包，生成预检报告。
4. 确认按钮号89–93、Buff ID190、QFunction标签无冲突后安装。
5. 启动后依次验证：地图静态按钮ID 5可打开；狂暴静态按钮ID 3打开与地图0 NPC相同对话且授予称号后变彩色；穿1件复活装备显示1次、穿2件显示2次；穿脱装备后属性数值刷新。
6. 未完成游戏内验收前保持candidate；失败时按安装事务逐字节回滚。

## 事件桥接安全规则

- QFunction只使用`XY_UI_QF_*`桥接标签，外部脚本继续使用`XY_UI_*`业务标签，两者不得同名。
- 每个显示项必须拥有独立的`#IF/#ACT`赋值块，不能落入上一项的负数归零条件中。
- 登录、穿戴、脱下先立即绘制，再于第5拍补绘最终业务值；固定使用`DELAYGOTO 5 @XY_UI_STATUS_REFRESH`。
- 旧`玄渊属性图标测试.txt@XYTEST_ATTR_BUFF_LOGIN`必须保持停用；它只能作为禁止参考的历史文件保留。
- 狂暴静态按钮只跳入QFunction桥接标签，再直接调用 `狂暴NPC接口.txt@XY_RAGE_NPC_MAIN`；NPC成功授予称号后通过安全刷新接口立即重画状态图标。
- 狂暴与地图必须接入界面已有的`[@CustomButtonClick]`和`<$CustomButtonID>`，不得再使用已验证无效的`ButtonClick89`透明覆盖路线。

详细变量标准见[属性锚定与扩展标准.md](docs/属性锚定与扩展标准.md)。
