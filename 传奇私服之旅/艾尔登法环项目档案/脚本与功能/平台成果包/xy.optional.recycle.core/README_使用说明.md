这是从 `D:\MirServer旧\AI_Handoff` 和旧服事务备份中审核、重建，并经当前服游戏验证通过的非常驻回收正式包。

- 成果包ID：`xy.optional.recycle.core`
- 版本：`1.0.2`
- 状态：`verified/optional`
- 不进入“一键安装常驻基础”
- 不自动创建NPC或屏幕图标
- 不自动回收
- 正式安装来源：`D:\XuanYuanDevPlatform\packages\verified\xy.optional.recycle.core`

旧资料中真正完成的是 `UserCmd31` 快捷回收白名单；24栏页面只有界面框架，真实分类和扣除规则当时明确未接入。明月端完整回收脚本使用另一套装备名、货币和界面资源，本包没有照搬。

`1.0.0-candidate.1` 曾把120段物品检测放入一个外部脚本；`1.0.1-candidate.2` 又拆成两个各60段的外部脚本。当前服M2对两种方案都明确报 `script error, load fail`，所以确认按钮能打开，但核心完全没有执行。

`1.0.2-candidate.3` 恢复旧版实际可工作的路线：120段物品检测和扣除奖励逻辑全部写入 `QFunction-0.txt` 的平台受管块，不再创建或调用任何外部回收脚本。用户于2026-07-20确认背包物品能够正常回收，因此正式晋级为 `1.0.2 verified/optional`。

## 平台安装

1. 打开 `D:\XuanYuanDevPlatform\bin\XuanYuanDevPlatform.exe`。
2. 在“目标管理”选择服务端根目录并识别。
3. 进入“成果包库”。
4. 选中“玄渊快捷回收（12项精确白名单）”。
5. 点击“生成预检报告”，确认只改：
   - `Mir200\Envir\UserCmd.txt`
   - `Mir200\Envir\Market_Def\QFunction-0.txt`
6. 确认安装，随后让M2重新加载脚本。
7. 游戏内输入 `@快捷回收`，阅读范围和奖励后再点“确认回收”。

CLI预检：

```powershell
D:\XuanYuanDevPlatform\bin\xydp-cli.exe preflight --server D:\MirServer --package xy.optional.recycle.core
```

CLI安装：

```powershell
D:\XuanYuanDevPlatform\bin\xydp-cli.exe install --server D:\MirServer --package xy.optional.recycle.core --yes
```

```text

```

```text

```

实际业务出口：

```text
@XY_RECYCLE_APPLY
```

### 屏幕图标

在已有 `[@CustomButtonClick]` 内确认自己的按钮ID后，只跳转公共标签：

```text
#IF
; 在这里填写自己的按钮ID判断
#ACT
GOTO @XY_RECYCLE_COMMAND
BREAK
```

图标资源、坐标和按钮ID不属于本包。

### NPC

当前正式版不开放跨文件NPC调用，因为本服已经实证外部 `#CALL` 无法加载回收业务标签。需要NPC入口时，应由平台在同一 `QFunction-0.txt` 的受管事件入口中跳转 `@XY_RECYCLE_COMMAND`；未经平台生成和验收的NPC适配脚本不得复制回收核心。

## 整套执行逻辑

1. 平台在 `UserCmd.txt` 唯一登记 `快捷回收 -> 31`。
2. 玩家输入 `@快捷回收`，引擎进入 `[@UserCmd31]`。
3. `@UserCmd31` 跳转 `@XY_RECYCLE_COMMAND`，再打开 `@XY_RECYCLE_PAGE`。
4. 页面明确显示范围、上限和奖励；取消时直接退出，不执行任何扣除。
5. 玩家点击确认后进入 `@XY_RECYCLE_CONFIRM`，再跳转同一QFunction受管块内的 `@XY_RECYCLE_APPLY`。
6. `@XY_RECYCLE_APPLY` 按规则表从上到下处理12种物品。每种连续执行10组：`CHECKITEM 1 -> TAKE 1 -> GIVE 金币 1000`。
7. 物品不存在时该组不执行；白名单外名称没有任何检测和扣除语句，因此不会被处理。
8. 全部处理结束后向玩家发送完成消息。整个流程不扫描部位、等级、Looks或模糊关键词。

## 游戏内验收

1. 背包放入白名单装备和一件非白名单物品。
2. 输入 `@快捷回收`，先点取消，确认任何物品和金币都不变化。
3. 再次输入命令并确认。
4. 确认白名单装备被回收，每件增加1000金币。
5. 确认非白名单物品仍在。
6. 同一种放入11件，确认本次最多处理10件。
7. 查看M2无脚本错误。
   - 不得出现任何 `script error, load fail: 玄渊功能\回收\回收核心`。
   - `QFunction-0.txt` 中不得存在回收功能的外部 `#CALL`。
8. 从“安装历史/回滚”逐字节回滚，并复查两个目标文件恢复。

本包已完成当前服核心回收游戏验收并晋级 `verified`。后续任何经济规则变更必须另起版本，不直接手改受管块；每个新版本仍需重新完成预检、M2、游戏和回滚验证。
