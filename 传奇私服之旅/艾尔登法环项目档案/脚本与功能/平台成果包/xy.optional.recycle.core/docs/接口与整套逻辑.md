# 快捷回收接口与整套逻辑

## 对外接口

玩家入口：`@快捷回收`。

平台命令登记：`UserCmd.txt` 中唯一行 `快捷回收\t31`。

同一 `QFunction-0.txt` 内部公共入口：`@XY_RECYCLE_COMMAND`。

同一受管块业务出口：`@XY_RECYCLE_APPLY`。

## 标签调用链

```text
@快捷回收
  -> [@UserCmd31]
  -> @XY_RECYCLE_COMMAND
  -> @XY_RECYCLE_PAGE
  -> 玩家取消：@EXIT，零扣除
  -> 玩家确认：@XY_RECYCLE_CONFIRM
  -> @XY_RECYCLE_APPLY
  -> 12项精确白名单逐项处理
  -> 完成提示
```

## 屏幕图标接口

只有当图标点击事件本身也位于 `QFunction-0.txt` 时，才允许在受管的 `[@CustomButtonClick]` 分支中执行：

```text
#IF
; 这里必须是已确认的按钮ID条件
#ACT
GOTO @XY_RECYCLE_COMMAND
BREAK
```

图标资源、按钮ID、坐标和显示文本不属于本包，必须由独立适配包管理。

## NPC边界

当前版本没有可跨文件调用的NPC接口。单外部脚本和60+60拆分外部脚本均在当前服出现 `load fail`，因此禁止NPC脚本使用 `#CALL` 调用回收业务标签，也禁止复制120段业务逻辑到NPC文件。

如果以后必须提供NPC入口，应先为当前引擎找到并实测一种不依赖失败外部 `#CALL` 的安全适配方式，再独立发布NPC适配包。核心回收包不因此创建NPC或MerChant行。

## 业务算法

每个白名单物品展开为10组相同逻辑：

```text
#IF
CHECKITEM 物品名 1
#ACT
TAKE 物品名 1
GIVE 金币 1000
SENDMSG 6 快捷回收：物品名，获得金币1000。
```

12种物品合计120组。每组先检测一件，检测成功才扣除一件并奖励1000金币；没有物品时该组不执行。白名单外物品没有对应语句，因此保持不变。

## 安装、幂等与回滚

- 安装只修改 `Mir200\Envir\UserCmd.txt` 和 `Mir200\Envir\Market_Def\QFunction-0.txt`。
- QFunction按GB18030写入平台受管块，不创建外部回收脚本。
- 重复预检必须为零变更。
- 同名命令、标签占用或受管块被手改时必须阻止。
- 回滚按事务逐字节恢复两个目标文件。
