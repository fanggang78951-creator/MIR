# M2 外部回收脚本加载失败修复

## 用户实测

2026-07-20 用户确认：回收页面和确认入口可打开，但背包物品没有被回收。

## 直接证据

当前服最新 M2 日志连续出现：

```text
script error, load fail: 玄渊功能\回收\回收核心.txt@XY_RECYCLE_APPLY
```

入口已经能打开，说明 `UserCmd31`、页面和确认标签有效；失败发生在确认后加载外部核心脚本时。

候选版 `1.0.0-candidate.1` 的单个外部脚本加载失败。随后 `1.0.1-candidate.2` 把逻辑拆成两个各60段的外部脚本，M2仍对两个文件都报 `load fail`。因此已经排除“脚本过长”假设，确认当前服务端的这条回收业务不能通过外部 `#CALL` 执行。

旧服已用版本把120段物品处理逻辑直接内联在 `QFunction-0.txt`，这是现有资料中唯一有实际工作记录的路线。`1.0.2-candidate.3` 因此改为：

- `UserCmd.txt` 只登记 `快捷回收\t31`；
- 页面、确认、12项白名单、120段 `CHECKITEM/TAKE/GIVE` 全部位于 `QFunction-0.txt` 的同一受管块；
- 不创建 `回收核心.txt` 或 `回收核心_B.txt`；
- 不包含任何回收功能外部 `#CALL`。

白名单、每种最多10件和每件1000金币完全不变。本修复仍保持 `candidate`，必须由用户完成游戏内扣除和奖励验收。

## 验收门

1. 平台预检只修改 `UserCmd.txt` 与 `QFunction-0.txt`；
2. 同一受管块中每项10组 `CHECKITEM/TAKE`，共120次 `GIVE 金币 1000`；
3. 目标服不存在平台遗留的 `回收核心.txt`、`回收核心_B.txt`，M2重载后不再出现相关 `load fail`；
4. 游戏内取消零变化、白名单扣除、非白名单保护和10件上限通过后，才能晋级 verified。
