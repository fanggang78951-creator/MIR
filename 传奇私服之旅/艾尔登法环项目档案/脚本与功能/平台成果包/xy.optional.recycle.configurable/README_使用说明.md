# 表格驱动装备自动回收

当前版本：`1.0.0-candidate.6`  
安装路线：平台“装备回收”专项页面，不能从通用成果包安装按钮直接安装。

## 用户只需要修改什么

唯一业务母表：

`D:\XuanYuanDevPlatform\所需材料表格汇总\19_装备回收配置.xlsx`

在“回收明细”中填写装备和奖励：

- 同一个“分类ID”的多件装备共用玩家面板中的一个勾选项。
- 同一格可写多件装备：`木剑|青铜剑|铁剑`；也可在Excel单元格内用`Alt+Enter`换行。
- 同格多件装备共享本行主奖励和附加奖励；需要不同奖励组合时分成多行填写。
- 旧的一行一件写法继续支持。平台会拆分后逐件精确检查，不支持通配符或模糊匹配。
- 新增一个从未出现过的“分类ID”，玩家面板自动增加一个勾选项。
- 面板每页固定显示3个分类，超过3类自动增加下一页。
- “启用=否”的行不会进入生成脚本。
- 主奖励和附加奖励都可选原生金币、原生元宝、原生灵符、原生金刚石或背包材料。
- 附加奖励三格全部留空时只发主奖励，保持旧表行为；只填写其中一部分会阻止预检。
- 背包材料必须填写准确的“奖励名称”；原生货币的奖励名称必须留空。
- 例如主奖励填写“原生金币、1000”，附加奖励填写“原生元宝、10”，脚本只回收一次装备并同时发放1000金币和10元宝。

## 装备提供“回收增加”

做装备母表 `09_装备批量生成.xlsx` 已增加“回收增加”列：

- 填 `20` 代表这件装备穿戴时，所有回收奖励在基础值上额外增加20%。
- 多件不同名称装备按表格数值直接相加，例如20%与30%合计50%。
- 每次手动回收或自动回收真正结算前，脚本都会重新读取当前穿戴装备；脱下后不会继续保留旧加成。
- 主奖励、附加奖励、原生货币和背包材料都使用同一个回收增加百分比。
- 例如基础奖励1000金币，当前装备合计回收增加20%，实际获得1200金币。
- 该属性只写入ItemDescList绿字，不占用M2自定义属性显示槽位。

生成或修改带“回收增加”的装备前，目标服必须先通过本专项页面安装candidate.6回收配置；缺少手动或自动回收锚点时，装备预检会阻止，绝不静默漏效果。

## 平台操作

1. 打开 `XuanYuanDevPlatform.exe`，进入“装备回收”。
2. 选择目标服务端；默认母表一般无需重新选择。
3. 点击“预检回收配置”。
4. 核对分类、装备、奖励、标志位、修改文件和阻止项。
5. 预检无阻止后点击“确认更新”。
6. 由用户自行重载或重启M2后，在游戏内验证。

平台只会受管修改：

- `Mir200\Envir\Market_Def\QFunction-0.txt`
- `Mir200\Envir\MapQuest_Def\QManage.txt`
- `Mir200\Envir\UserCmd.txt`

平台重建回收配置时，会校验并保留由做装备工具写入QFunction、QManage的“回收增加”受管分支；两处不一致、重复或被手改时直接阻止更新。

安装前会逐文件备份；预检后母表或目标文件发生变化会阻止安装；安装失败不留半成品；安装后可用事务号逐字节回滚。

## 玩家入口与触发规则

- 背包装备回收按钮：`CustomButtonID=21`
- 玩家命令：`@快捷回收`
- QFunction入口：`GOTO @XY_RECYCLE_COMMAND`
- 自动检测：人物定时器 `OnTimer20`
- 默认只在背包空余格数少于40时，一次性回收全部已勾选类别中的现有装备。
- 每个装备分支必须先无条件清零删除前、删除后和实际删除数量，再用`CHECKITEM`确认背包确实存在，存在时才计数、删除和结算。
- 只有实际删除数量大于0才允许发奖；空背包不会沿用上一次回收数量，也不会出现重复金币或元宝。
