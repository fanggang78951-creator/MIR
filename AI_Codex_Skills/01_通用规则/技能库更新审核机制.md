# 技能库更新审核机制

记录来源：XY-SKILL-002
记录时间：2026-06-16 09:51:04

## 一、基本原则
每个 AI_Handoff 任务完成后，Codex 不得自动把所有经验都写成永久规则。
必须按以下流程处理：

1. 任务执行完成。
2. 输出结果_outbox.md。
3. 判断本任务是否产生可复用经验。
4. 将可复用经验分为以下三类：
   - 已验证技能
   - 静态确认但待游戏验证
   - 风险记录或避坑记录
5. 写入技能库前，必须明确证据来源。
6. 不得把猜测写成规则。
7. 不得把一次偶然现象写成通用规则。
8. 不得擅自覆盖旧技能文件。
9. 更新技能库时必须保留时间、任务编号、证据路径和验证状态。

## 二、验证状态定义

### 已验证技能
必须满足：
1. 文件或数据库层面已确认。
2. 游戏内或实际运行已验证。
3. 没有出现 M2 报错或游戏红字。
4. 可复用到同类任务。

### 静态确认但待游戏验证
满足：
1. 文件或数据库层面已确认。
2. 静态自检通过。
3. 但尚未做游戏内测试。
4. 必须标注“待游戏验证”。

### 风险记录或避坑记录
满足：
1. 发现错误、报错、覆盖风险、重复声明风险。
2. 即使尚未完成修复，也应记录为避坑经验。

## 三、每次任务结束后必须在结果中增加

【技能库更新判断】

内容包括：
1. 本任务是否产生可复用技能：
2. 建议写入哪个技能文件：
3. 证据来源：
4. 验证状态：
5. 是否需要用户或 ChatGPT 确认后再写入：
6. 本次是否已经写入技能库：

## 四、严禁行为
1. 禁止把“待验证”写成“已验证”。
2. 禁止把“某个项目有效”写成“所有引擎通用”。
3. 禁止覆盖旧经验。
4. 禁止删除旧技能。
5. 禁止无证据总结。
6. 禁止隐藏风险。

# XY-SKILL-003 审核机制补充：待验证技能升级为已验证技能

记录时间：2026-06-16 12:37:07

当某条经验先前标记为“静态确认，待游戏验证”时，只有满足以下条件，才允许升级为“已验证技能”：

1. 用户明确反馈已经完成游戏内测试。
2. 测试结果证明该规则实际生效。
3. 没有出现M2报错或游戏红字导致功能失败。
4. 经验中必须保留：
   - 原始任务编号
   - 验证时间
   - 验证状态
   - 适用项目
   - 关键字段
   - 踩坑记录
   - 后续应用规则

本次升级案例：

XY-A-005 材料叠加规则已由用户确认游戏内测试通过。
因此升级为已验证技能：

StdMode=46
DuraMax=1000
OverLap=2
