# 翎风时装装备外观与内观特效的对应关系

> 2026-09-23 正式端游戏验证记录。本文只记录可复用的引擎规律和验收边界，不包含 PAK 密码、素材包或正式数据库。

## 两条显示链必须成套对应

- 人物在地图中的武器、衣服动作外观由装备 `StdItems.Shape` 和对应动作资源决定；背包、装备栏的静态图由 `Looks` 及 Items、DnItems、StateItem 资源决定。
- 装备内观动画走引擎原生特效链：`EffectImageList.txt` 注册资源 → `EffectList.txt` 定义帧、位置和速度 → `EffectItemList.txt` 按物品名绑定。它不能代替 `Shape` 的人物动作外观，也不能自动把旧静态图换成同套素材。
- `EffectImageList.txt` 的资源编号按列表物理顺序、从 0 开始；迁移供体时按资源文件名重新解析目标编号，不能照抄供体编号。
- 登录器须按其当前实际生效的 PAK 规则注册资源，由原生制作工具保存和生成；不能用“自动读取”覆盖已有密码规则。密码只留在本地配置，不进 Git。

## 时装的实机发现

翎风官方时装说明把时装衣服列为 `StdMode=66/67`、时装武器列为 `68/69`，示例中的时装装备也使用非零 `Shape`。参见[翎风引擎时装说明](https://www.5cq.com/help/%E7%BF%8E%E9%A3%8E/topics/%E6%B8%B8%E6%88%8F%E5%BC%95%E6%93%8E%E5%8F%8D%E5%A4%96%E6%8C%82%E7%B3%BB%E7%BB%9F/%E5%85%B6%E4%BB%96%E7%9B%B8%E5%85%B3%E8%B5%84%E6%96%99/%E6%97%B6%E8%A3%85.html)。

本次最初只给 24 件时装绑定了供体内观特效，保留原 `Shape=0` 和原 `Looks`。正式游戏出现两个不同症状：开启时装模式后地图人物不显示时装装备；手持内观中旧蓝色静态武器与新橙色动画叠在一起。普通武器、衣服动作帧当时正常，不能据此推断时装链也正常。

单件验证选“潮葬礼剑”：保持已有内观特效绑定 `30015` 不变，只将它的 `Shape` 从 `0` 改为供体的 `556`、`Looks` 从 `8912` 改为同一供体的 `60013`。用户在正式游戏确认地图人物显示时装武器，手持内观也协调。随后按已有供体映射仅补齐其余 23 件时装的 `Shape/Looks`（9 件武器、14 件衣服）；用户反馈 24 件均正常。此次批量补齐没有更改普通装备、特效定义、登录器或增加地面特效。

因此，给时装迁移视觉效果时，不要把“特效绑定成功”等同于“完整替换”。应同时核对同一供体的 `Shape`、`Looks`、动作 PAK 和内观特效，再分别验收地图人物动作、背包/装备栏静态图与内观动画。衣服动作素材允许按项目需求复用，但复用不等于跳过逐件映射检查。

## 安全实施与验收

1. 先从引擎原生界面和供体文件确认字段与资源链；只检查本次指定装备及其引用的资源，不扫描整个素材库。
2. 明确正式/隔离端、物品名与 `Idx`；在客户端和 M2 退出后备份目标数据库及将改动的表。不要触碰无关装备或属性列。
3. 用一件时装作最小验证：保持特效绑定不变，只使 `Shape/Looks` 对齐已绑定特效的供体；游戏确认后再扩展同类。若未通过，先回滚该件并重新定位，不叠加猜测性补丁。
4. 批量时逐行核对原值、装备类别、供体 `Shape/Looks`、动作包、静态包、特效绑定与资源编号；写入后做数据库完整性检查、备份差异核验和目标回读。
5. 文件级验证只证明配置已写入。地图人物、静态图、内观动画是否显示和协调，仍须由用户在正式游戏中分别验收；不需要地面特效时，其资源位保持关闭。
