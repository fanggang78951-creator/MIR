# 首爆系统设计

**目标**：为聆风/LFM2 服务端提供一个只在玩家首次拾取指定物品时发放奖励的独立脚本框架，不携带真实物品清单，也不写入任何服务端。

## 设计结论

- 触发入口使用 `[@PickUpItemEX]`，并先执行 `LINKPICKUPITEM`，读取 `$PICKDROPITEMNAME`。
- 奖励配置使用一个带 `[首爆奖励]` 节的 TXT 文件，格式为 `物品名称=奖励数量=状态=剩余次数=奖励类型`。
- 本轮只提供注释示例，不植入真实物品、玩家名或历史记录。
- 领取记录写入独立 `已领取奖励.txt`，并同步把配置行状态更新为玩家名和 `0`，从而跨 M2 重启保留。
- 成功首爆执行奖励、`SceneShake`、`SENDMOVEMSG` 和 `MessageBox`。
- 未配置物品、已领取物品、状态不是 `未领取`、剩余次数不是 `1` 或奖励类型不支持时均不发奖。

## 文件边界

交付包位于当前工作区的 `首爆系统候选包`，只包含脚本、TXT 配置/说明和本地验证器。两个参考服务端只读，不作为运行时依赖；不修改 `D:\MirServer`、参考端、客户端资源、平台 EXE 或正式成果包。

## 奖励类型

首版兼容两个参考端已出现的命令映射：`元宝 -> GAMEGOLD`、`金币 -> GOLDCOUNT`、`金刚石/沉默币 -> GAMEDIAMOND`。未识别类型只提示配置错误，不记录为已领取。

## 验证

本地验证器检查脚本关键命令、相对路径、配置语法、首次拾取、重复拾取、未配置物品和未知奖励类型；验证器不调用 M2、不修改服务端文件。
