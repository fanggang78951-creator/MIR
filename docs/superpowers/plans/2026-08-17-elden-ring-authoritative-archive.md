# 《艾尔登法环》传奇脚本与功能权威资料库实施计划

**目标：** 以本机真实脚本、正式服务端收据、E 盘平台成果包、接口文档、配置母表和验收证据为依据，建立可追溯、可校验、可持续更新的法环脚本与功能母库，并提交到 GitHub 私有仓库 `fanggang78951-creator/MIR`。

**用户最终范围：** 只整理脚本类、功能类成果。地图、地图号、坐标、客户端地图资源、装备来源编号和装备内容均不在本轮范围。装备回收、洗练、图鉴、合成等作为“功能系统”可以归档，但不盘点具体装备编号与装备设计。

**保护边界：** 本轮只读 `D:\MirServer`、`E:\XuanYuanDevPlatform` 和历史资料；不运行、关闭或启动 M2/游戏引擎，不修改正式服务端、数据库或平台母库。

## 实施步骤

1. 核验 Git 仓库、远端、忽略规则与工作区状态；建立独立功能分支。
2. 读取交班索引、最近指针及限定数量的相关历史记录，区分设计、写入、部署、游戏验收、废止与待确认。
3. 只读解析平台成果包清单、正式服 `.xydp/installed.json`、共享事件脚本、功能脚本、接口文档和配置母表。
4. 建立功能总台账、接口台账、正式服托管块台账、文件哈希清单、版本漂移清单和脚本引用问题清单。
5. 保存正式服功能脚本的逐字节原始快照，并生成便于 GitHub/ChatGPT 阅读的 UTF-8 副本；保留源编码与 SHA-256。
6. 建立核心档案、当前有效功能总档、变更记录、每日更新、实施快照和两份 XLSX 台账。
7. 使用表格工具生成 XLSX，执行公式错误扫描和可视化渲染复核。
8. 验证重复标签、受管块配对、可解析的 `#CALL` 目标、哈希、Git 跟踪范围和远端可达性。
9. 只暂存本轮档案目录、实施计划和必要的 `.gitignore` 放行规则，提交并推送功能分支。
10. 生成本轮 TXT 交班记录，更新任务总结索引和最近任务指针。

## 验收标准

- 核心档案和脚本/功能台账全部存在且能打开。
- 正式服已装版本与平台当前版本逐项对比，漂移给出具体包和两个版本。
- 「已部署待实测」与「游戏内实测通过」不得混写；候选包的局部验收证据单独注明。
- 每份正式脚本快照都有源路径、大小、时间、编码和 SHA-256。
- 共享脚本重复标签、受管块配对和可解析调用链均有静态审计结果。
- 地图和装备内容不进入本轮权威库。
- `git status`、文件清单、哈希清单和 GitHub 远端分支提交能互相对应。
